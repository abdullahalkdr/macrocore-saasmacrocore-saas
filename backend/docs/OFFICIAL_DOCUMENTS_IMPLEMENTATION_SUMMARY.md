ملاحظة: هذي الوحدة مختلفة عن "موديول المستندات" الأصلي بالسبك (رفع/تخزين تراخيص وعقود بصلاحية). المستخدم زوّدني بصورتين تحددان المطلوب الفعلي: **مولّد مستندات صادرة** (خطابات، شهادات، إيصالات) برقم مرجعي تلقائي وطباعة/PDF — مو تخزين ملفات موجودة. بنيت حسب الصور بالضبط.

## ما تم بناؤه

### 1. Schema (Migration 008)
📄 `backend/docs/MIGRATION_008_official_documents.sql`

جدول `official_documents`: نوع المستند، رقم مرجعي (UNIQUE per company)، عنوان، جهة/شخص موجّه له (إما موظف مسجّل أو نص حر)، تاريخ، نص المستند.

### 2. Backend
- **`nextReferenceNumber()`**: يولّد `COR-{سنة}-{تسلسل}` (مثال: `COR-2026-0004`) — تسلسلي لكل شركة/سنة، بحساب أعلى رقم موجود +1 (بـ JS مو SQL regex، عشان التوافق مع pg-mem)
- Endpoints: `GET/POST/PATCH/DELETE /api/official-documents`، و`GET /api/official-documents/next-reference` (يعرض الرقم المرجعي القادم بالفورم قبل الحفظ، مطابق للصورة)
- "الجهة الموجّه له": إما `addressed_to_employee_id` (موظف من القائمة) أو `addressed_to_name` (نص حر لجهة خارجية) — الاثنين متنافيان

### 3. Frontend
- **OfficialDocumentsPage**: مطابقة للصور — قائمة بالأعمدة (رقم مرجعي، نوع، عنوان، جهة/شخص، تاريخ) + مودال إنشاء/تعديل بنفس ترتيب الحقول
- أنواع المستند: خطاب رسمي، شهادة راتب، شهادة خبرة، إيصال استلام، أخرى
- زر **PDF/طباعة**: يفتح نافذة جديدة بتنسيق مستند مطبوع (ترويسة برتقالية، رقم مرجعي وتاريخ، نص المستند) ويستدعي `print()` — بدون أي مكتبة خارجية جديدة
- إضافة الصفحة لـ Sidebar تحت "Management"

## قرارات تقنية

| القرار | السبب |
|---|---|
| ترقيم تسلسلي محسوب من أعلى رقم موجود، مو جدول عدّاد منفصل | أبسط للتنفيذ، كافي لحجم عمل كشك واحد؛ فيه احتمال نادر لتضارب بحالة إنشاء متزامن — موثّق كـ tradeoff بالكود |
| الطباعة عبر `window.print()` بنافذة منسّقة | يحقق "PDF/طباعة" بدون إضافة مكتبة PDF جديدة (المتصفح نفسه يقدر يحفظ كـ PDF من نافذة الطباعة) |
| "الجهة الموجّه له" تدعم موظف مسجّل أو نص حر | يغطي الحالتين بالصورة: خطاب لجهة خارجية (وزارة...) وشهادة لموظف داخلي |
