## ما تم بناؤه

### 1. Schema (Migration 007)
📄 `backend/docs/MIGRATION_007_advanced_payroll.sql`

- `employees.wage_type` (`monthly` | `hourly`، افتراضي `monthly`) + `employees.hourly_rate`
- `payroll`: أعمدة جديدة `wage_type`, `hourly_rate`, `hours_worked`, `attendance_deduction` (snapshot عند التوليد)
- جدول جديد `payroll_adjustments` — بنود يدوية (مكافأة/خصم) بخط تفصيلي، بدل رقم واحد فقط

### 2. Backend
- **`computeDeduction()`** بقيت تحسب خصم التأخير لموظفي الراتب الشهري فقط (راجع القرار أدناه)
- **`payroll.controller.ts create()`** أعيد بناؤه بالكامل:
  - يحسب مدى الشهر (أول/آخر يوم) بـ JS، بدون SQL date functions غير مدعومة بـ pg-mem
  - يجمع `attendance_records.deduction_amount` تلقائياً للشهر ويطرحها من الصافي
  - للموظف بالساعة: يحسب ساعات العمل من فروقات clock_in/clock_out المسجّلة، ويحسب الأساسي = ساعات × سعر الساعة
  - يقبل مصفوفة `adjustments` (بنود يدوية) ويحفظها بجدول منفصل
- `GET /api/payroll/:id` جديد — يرجع الراتب + البنود التفصيلية
- `employees.controller.ts` صار يدعم `wage_type`/`hourly_rate` بالإنشاء والتعديل

### 3. Frontend
- **EmployeesPage**: اختيار نظام الأجر (شهري/بالساعة) + حقل سعر الساعة يظهر بدل الراتب لما يكون بالساعة
- **PayrollPage**:
  - نموذج التوليد يعرض ملاحظة توضيحية (الأساسي يُحسب تلقائياً للموظف بالساعة، وخصم التأخير يدخل تلقائياً)
  - بنود إضافية ديناميكية (إضافة/حذف أسطر مكافأة أو خصم بعنوان ومبلغ)
  - الجدول الرئيسي يعرض نظام الأجر وخصم التأخير التلقائي والصافي، مع صف تفصيلي قابل للطي (ساعات العمل، سعر الساعة، تفصيل كل بند)

## قرار تقني مهم اكتشفته أثناء البناء: تجنّب خصم مزدوج

بالأول خطط لي أطبّق خصم التأخير على موظفي الأجر بالساعة أيضاً (نفس منطق الشهري، بس بسعر الساعة). لكن اكتشفت هذا خطأ حسابي:

- ساعات العمل تُحسب من الفرق الفعلي بين `clock_in` و`clock_out`
- لو الموظف تأخر، ساعات عمله تنقص تلقائياً (دخل متأخر = ساعات أقل = أجر أقل) — الخصم موجود ضمنياً بالفعل
- لو ضفت خصم تأخير منفصل فوق هذا، بيصير تغريم نفس الدقائق مرتين

**الحل:** خصم التأخير التلقائي يطبّق بس على الراتب الشهري (اللي فعلاً محتاج تصحيح، لأنه رقم ثابت ما يتأثر بساعات الحضور). الموظف بالساعة أجره أصلاً دقيق لأنه مبني على وقت الحضور الفعلي.

## قرارات تقنية أخرى

| القرار | السبب |
|---|---|
| `attendance_bonus`/`other_deductions` القديمة بقيت كما هي | توافق خلفي — ما لمستها، البنود الجديدة (`payroll_adjustments`) إضافية فوقها |
| `wage_type`/`hourly_rate` تُحفظ snapshot بجدول payroll | نفس منطق `base_salary` الموجود أصلاً — تغيير لاحق ما يأثر رجعياً على رواتب مولّدة |
| حساب مدى الشهر ونطاق الساعات بـ JS مو SQL | pg-mem ما يدعم `EXTRACT`/`AGE`/`date_trunc` — نفس القيد الموثق بالميقريشن 005 |
